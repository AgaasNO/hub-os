## The question this session answers

**What kind of memory is the vault, and how does that change its scope, name, and boundary with the rest of the framework?**

The current hub-os framework (v0.2.4) calls Layer 4 "Metacognition (Vault)" and says its job is *WHY* — why decisions were made, what was learned. That framing is defensible but loose. A sharper framing has been surfaced and parked for this session:

**The vault is semantic memory. Everything outside the vault is procedural / structural memory.**

- **Procedural memory** — *how to do things.* Routines, rules, routing, state, task mechanics, hooks, credentials. Answers *"how does the system behave?"*
- **Semantic memory** — *what things mean.* Concepts, ideas, people as characters, projects as philosophies, decisions as reasoning. Answers *"what is this thing, abstractly?"*

Same entity queried from each layer returns different kinds of payloads. `[[Black Rabbit Games]]` from procedural memory gives you routing rules and task state; from semantic memory it gives you the manifesto, the philosophy, the people in its orbit, the reasoning behind decisions. Two genuinely different kinds of recall. See `[[Vault is semantic memory]]` for the full worked-out distinction, origin notes, and the retrieval test.

Under this framing, *scope* becomes downstream. Semantic memory about concepts is inherently user-scoped — `[[Alex]]` as a character doesn't care which hub you're working in — so a shared `~/thehub/vault/` is the natural home. Hub-scoped per-hub vaults fragment the graph and lose most of the wikilink value.
